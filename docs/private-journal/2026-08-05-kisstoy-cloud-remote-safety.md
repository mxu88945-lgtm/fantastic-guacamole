# 私人项目日记｜KissToy 云端遥控安全版

- 日期：2026-08-05
- 状态：仅完成方案审阅，暂停实施
- 参考仓库：https://github.com/AMX-Claw/kisstoy-cloud-remote
- 原则：不在本仓库保存真实 `group`、`user_id`、连接地址、访问令牌或设备隐私数据

## 已确认的路线

参考方案通过下面的链路绕开 Intiface：

```text
AI / MCP → KissToy 云端 WebSocket → 手机 App → Bluetooth → 设备
```

路线在协议与架构上可行，但参考实现目前不能原样用于真实设备控制。

## 审阅发现

1. **急停不可靠**  
   旧波形没有真正的取消机制。`toy_stop` 只发送一次归零指令；旧任务下一拍仍可能再次发送非零强度。多个波形也可能同时运行并争抢同一马达。

2. **长任务与 Worker 生命周期不匹配**  
   参考实现依赖 `ctx.waitUntil()` 在响应后继续运行，而 Cloudflare Worker 对这类后台执行的延续时间有限。README 所述的长时间序列不能据此稳定实现。

3. **异常退出缺少强制归零**  
   序列执行没有完整的 `finally` 归零保护。任务取消、WebSocket 异常或 Worker 中断时，无法保证最后一定发送停止指令。

4. **连接参数等同于控制凭证**  
   `group` 与 `user_id` 被直接放在 MCP URL 查询参数中，完整 URL 一旦泄露就可能被用于发送控制命令。参考实现也没有额外鉴权。

5. **设备映射写死**  
   当前设备 ID 与马达 ID 针对 PLY5 固定设置，其他 KissToy 型号不能直接假定兼容。

6. **执行成功缺少设备确认**  
   当前逻辑主要确认设备在线，并未获得可靠的设备执行回执，因此“在线”不能等同于“已按指令执行”。

## 安全版目标架构

- 使用 Cloudflare Durable Object 为每个设备会话提供唯一协调器。
- 同一时间只允许一个活动波形。
- 每个任务使用 generation token 或 AbortController；新任务启动前先取消旧任务并归零。
- `toy_stop` 拥有最高优先级：取消活动任务、推进 generation、立即归零，旧循环不得再次写入。
- 所有执行路径在 `finally` 中发送归零指令。
- 增加短周期心跳与 watchdog；心跳消失时自动归零。
- 使用稳定 MCP 地址与独立鉴权；轮换的 KissToy 会话参数只保存在服务端。
- 默认设置强度、单次时长和重复次数上限。
- 电刺激能力默认关闭，未经单独启用不暴露对应工具。
- 保留手机 App 断连、关闭蓝牙及设备电源等本地物理停止方式。
- 按设备型号配置 device/motor 映射，不再写死在业务代码中。

## 计划测试

- 新序列能取消旧序列，且旧序列永不恢复输出。
- 急停在序列间隔、网络抖动和并发请求下均保持归零。
- WebSocket 断开、Worker 异常和任务取消时均执行归零。
- 未授权请求无法调用任何控制工具。
- 日志、错误信息和 URL 不暴露会话凭证。
- 模拟设备先通过完整回归，再以最低强度、最短时长做真人设备验证。
- 不支持的设备型号明确拒绝执行，不猜测马达编号。
